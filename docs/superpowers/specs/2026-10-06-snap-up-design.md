# snap-up 설계

작성일: 2026-10-06 · 상태: 설계 승인, spec 검토 대기

## 1. 목적

직접 찍은 스냅 사진을 프롬프트로 편집하는 개인용 웹 도구. 혼자 사용하며 Vercel에 배포해 URL로 접근한다.

- 수정 대상 선택: 배경 / 인물 / 없음
- 사용자 프롬프트로 대상 수정
- 비율 변경: 확장 시 늘어난 공백을 AI로 채움(outpainting), 크롭 시 로컬 처리
- 결과 위에 이어서 편집(체이닝)

### 절대 조건과 정의

| 조건 | 이 프로젝트에서의 정의 | 보장 방법 |
|---|---|---|
| 1. 지정 외 수정 금지 | 승인 영역 A 밖의 모든 픽셀이 현재 기준 이미지와 동일(차이 0px) | 최종 합성에서 A 밖 가중치 = 0, 저장 PNG 재디코딩 검증 |
| 2. 원본·고화질 유지 | 출력 해상도 = 기준 이미지 픽셀 밀도, 무손실 PNG 저장 | 원본 해상도 합성. AI 영역은 업스케일로 다소 무를 수 있음(알려진 한계) |
| 3. AI 워터마크 금지 | 보이는 워터마크 없음 + C2PA 등 메타데이터 없음 | 프롬프트에 텍스트·로고·워터마크 금지, 브라우저 Canvas 재인코딩으로 메타데이터 제거 |

픽셀 내장형 비가시 신호는 OpenAI가 공개하지 않아 검증 대상에서 제외한다.

### 성공 기준

- 보호 영역 변경 0px이 매 결과마다 검증되어 표시된다.
- 출력 해상도가 기준 이미지와 같다(확장 시 같은 픽셀 밀도로 커진다).
- 결과물에 보이는 워터마크와 메타데이터가 없다.

## 2. 스택과 구조

Next.js(App Router) + TypeScript, Vercel 배포(Fluid compute, Node 런타임). 테스트는 Vitest.

```
app/page.tsx              편집 화면 1개 (client component)
app/api/segment/route.ts  fal BiRefNet 프록시 → 인물 마스크
app/api/edit/route.ts     OpenAI gpt-image-2 edits 프록시 (응답 스트리밍)
middleware.ts             HTTP Basic Auth, 전 경로
lib/mask.ts               마스크 업스케일·반전·브러시 반영·안쪽 페더
lib/canvas.ts             정규화, 비율 확장/크롭 좌표와 역변환, 모델 size 계산
lib/composite.ts          최종 합성 + 보존 검증
lib/prompt.ts             프롬프트 조립
```

환경변수(서버 전용): `OPENAI_API_KEY`, `FAL_KEY`, `APP_PASSWORD`.

원본과 모든 버전은 브라우저 메모리에만 둔다. 외부로 나가는 것은 모델 해상도로 축소한 이미지(fal, OpenAI)뿐이다.

## 3. 처리 흐름

1. **업로드·정규화**: `createImageBitmap(file, { imageOrientation: 'from-image' })` → 8bit sRGB 캔버스. 입력 40MP 초과는 거부.
2. **대상 선택**: 배경 / 인물 / 없음.
3. **세그멘테이션**: 축소본(긴 변 2048px 이하, JPEG q0.92)을 `/api/segment`로 보내 인물 matting alpha를 받고 기준 이미지 크기로 업스케일. 배경 선택 시 반전. 결과는 버전별로 캐시하며, 배경↔인물 전환은 재호출 없이 반전한다.
4. **마스크 확인**: 승인 영역을 반투명 오버레이로 표시, 더하기/빼기 브러시(크기 조절)로 수정.
5. **비율**: 확장이면 캔버스를 늘리고 새 영역을 A에 추가. 크롭이면 좌표만 기록하고 최종 단계에서 로컬 크롭.
6. **편집 호출**: 작업 캔버스와 API 마스크를 모델 size로 축소해 프롬프트와 함께 `/api/edit` 1회 호출(대상 수정 + 공백 채우기 동시).
7. **합성**: AI 결과를 원본 좌표로 업스케일 → `out = W·AI + (1−W)·기준`.
8. **검증**: PNG로 인코딩 후 재디코딩, W=0 픽셀이 기준과 모두 같은지 검사. 통과 시 "보호 영역 변경 0px" 표시.
9. **채택/다시**: 채택하면 새 버전이 되어 다음 편집의 기준이 된다. 다시는 프롬프트를 바꿔 재생성.

AI 호출 생략 규칙:
- 대상 없음 + 확장 없음 → AI 호출 없음(크롭만 로컬 처리).
- 대상 없음 + 확장 → outpainting만, 프롬프트는 선택 사항.

## 4. 화질·합성

### 모델 size

- 작업 캔버스 비율로 `WxH` 계산: 양 변 16의 배수, 총 픽셀 ≤ 2560×1440(3,686,400), 비율 ≤ 3:1. 3:1 초과 비율은 UI에서 차단.
- 2560×1440 초과(experimental)는 쓰지 않는다.

### 전송

- 입력 이미지: JPEG q0.92. 압축 손실은 AI 영역에만 영향을 준다(영역 밖은 기준 이미지로 덮음).
- 마스크: RGBA PNG, 입력과 같은 픽셀 크기.
- 요청 총합 4.5MB 초과는 클라이언트와 서버 모두에서 차단.
- 응답: OpenAI 응답 본문을 그대로 스트리밍(`new Response(res.body)`)해 Vercel 응답 크기 제한을 피한다. 출력 형식은 PNG. 클라이언트가 JSON의 Base64를 디코딩한다.
- `input_fidelity`는 보내지 않는다(gpt-image-2는 항상 high).

### 마스크 3종

내부 값은 편집량(1 = 편집).

| 마스크 | 정의 |
|---|---|
| 승인 영역 A | 세그멘테이션(배경이면 반전) + 브러시 수정 + 확장 공백 영역 |
| API alpha | `alpha = 1 − dilate(A, 32px)`(alpha 0 = 편집, 모델 해상도 기준). A 전체를 32px 넓혀 모델이 경계·이음새를 이어 그리게 한다. 넓힌 부분은 합성 가중치 W가 0이라 결과에 반영되지 않는다 |
| 합성 가중치 W | `min(A, blur(A))`. A 밖은 정확히 0, 페더는 A 안쪽에만 생긴다 |

인물/배경 경계는 matting alpha를 그대로 W로 쓴다. 머리카락 사이로 옛 배경색이 비치는 현상은 MVP에서 감수한다.

### 업스케일·합성

- `drawImage` + `imageSmoothingQuality: 'high'`.
- 합성은 메인 스레드에서 픽셀 루프 1회로 처리하고 진행 상태를 표시한다.

## 5. 비율 변경

- 프리셋: 원본 · 1:1 · 4:5 · 3:4 · 2:3 · 9:16 · 3:2 · 4:3 · 16:9.
- [확장(AI 채움) / 크롭] 토글, 기본은 확장.
- 앵커: 확장은 새 프레임 안에서 기준 이미지를 드래그해 배치(기본 가운데), 크롭은 크롭 프레임을 드래그.
- 상한: 확장 후 면적 ≤ 기준 이미지의 2배(단계마다 적용), 출력 ≤ 60MP.
- 출력은 기준 이미지의 픽셀 밀도를 유지한다. 예: 6000×4000 → 4:5 확장 → 6000×7500.

## 6. 버전(체이닝)

- 기준 이미지 = 가장 최근에 채택한 결과. 처음 기준은 원본.
- 채택할 때마다 PNG Blob으로 저장하고, 하단 썸네일 줄에서 이전 버전을 눌러 되돌아간다.
- 최대 10개 보관. 넘으면 가장 오래된 중간 버전부터 버리고, 원본은 항상 유지.
- 한 번도 승인 영역에 들어가지 않은 픽셀은 모든 버전에서 원본과 동일하다.
- 새로고침하면 작업이 사라진다. `beforeunload` 경고만 띄운다.

알려진 한계: 같은 영역을 반복 편집하면 축소·업스케일이 누적되어 화질이 떨어진다.

## 7. 프롬프트 조립

사용자 입력(한국어 그대로)을 고정 지시문으로 감싼다.

- 기본: 마스크 영역만 수정, 기준 이미지의 조명·색온도·원근·그레인에 맞출 것, 텍스트·로고·워터마크 금지.
- 배경 수정: 새 배경을 인물의 광원 방향·색온도에 맞출 것(인물은 다시 조명하지 않음).
- 확장 포함 시: 확장 영역은 원본 장면을 자연스럽게 이어서 채울 것.

## 8. 보안

- `middleware.ts` Basic Auth로 페이지와 `/api/*` 전체를 보호, 비밀번호는 상수 시간 비교.
- `APP_PASSWORD`가 없으면 전부 차단(fail closed).
- API 키는 서버 전용(`NEXT_PUBLIC_` 금지).
- API 입력 검증: multipart만 허용, 요청 4.5MB 이하, 이미지 크기는 모델 제약 안, 프롬프트 2000자 이하.
- URL 입력은 받지 않는다. 파일 바이트만 받는다.
- 라우트: `runtime = 'nodejs'`, `maxDuration = 300`.
- rate limit 없음(단일 사용자 + Basic Auth).

## 9. 에러 처리

자동 재시도는 하지 않는다(비용).

| 상황 | 처리 |
|---|---|
| OpenAI 콘텐츠 정책 거부 | "정책상 거부" 안내, 프롬프트 수정 유도 |
| 429 · 5xx · 타임아웃 | 원인별 안내 + 수동 재시도 버튼 |
| fal 세그멘테이션 실패 | 안내 후 브러시로 직접 마스크를 그려 진행 |
| 크기·비율 초과 | 클라이언트 선차단, 서버 400 |
| 보존 검증 실패 | 채택·다운로드 차단, 기준 이미지 유지 |
| 생성 중 재클릭 | 버튼 비활성화로 중복 호출 차단 |

## 10. 테스트

Vitest.

- 단위
  - 모델 size 계산(16의 배수, 3:1, 픽셀 상한)
  - 확장/크롭 좌표와 역변환
  - `W = min(A, blur(A))`가 A 밖에서 0
  - 합성 + 보존 검증: 합성 이미지에서 보호 영역 차이 0px, 고의로 1px 바꾸면 실패
  - 프롬프트 조립
- 라우트(fetch mock)
  - 인증 거부/통과, `APP_PASSWORD` 미설정 시 차단
  - 크기 초과 거부, URL 입력 거부
- 실측(구현 계획 첫 단계)
  - 실제 스냅 사진으로 gpt-image-2 edits의 RGBA 마스크 수용 여부, 지연, 응답 크기
  - fal BiRefNet Portrait vs Matting 모델 경계 품질 비교
  - Vercel Preview에서 4.5MB 초과 스트리밍 응답 통과 여부

## 11. 범위 밖 (필요가 확인되면 추가)

- 인물 bbox 크롭 고해상도 편집, 두 단계 호출
- 머리카락 halo 제거(foreground estimation)
- AI 영역 업스케일러(ESRGAN 등)
- JPEG 저장 옵션, 비율 직접 입력
- IndexedDB 작업 저장, Web Worker 합성
- Vercel Blob 업로드
